## Установка

**Windows 10/11 x64**: скачайте ZIP с названием `Windows-x64`, распакуйте **полностью**, запустите `.exe` или `Start-*.bat` из извлечённой папки. DLL, Python и Qt находятся рядом — **не переносите отдельно один EXE**.

**macOS Apple Silicon (macOS 14.4+)**: скачайте `macOS-arm64.zip`, распакуйте, откройте `.app` двойным щелчком. Intel Mac не поддерживается в этих сборках. Подпись пока не Developer ID / нотариализация, поэтому ОС может предупредить о неизвестном разработчике. Не отключайте защиту системы глобально.

Каждый Release включает `SHA256SUMS.txt` для сверки скачанного архива. В обоих приложениях используется **локальная симуляция**, а не физические роботы.

## Самый первый выпуск (вручную, проверенные архивы)

В первый выпуск входят **четыре уже подготовленные сборки**, по две на каждую линию. Для публикации используется отдельный локальный комплект `OperatorComplex-dual-beta.1-release-kit.zip` и `publish-both-betas.sh`. Он проверяет контрольные суммы, репозиторий, коммиты и отсутствие тегов, затем создаёт **два независимых** prerelease. Через Git пласты бинарников не проходят.

**Оба первоначальных выпуска опубликованы 19 октября 2026 года:** [Technical 0.3 Beta 1](https://github.com/Hazernit/operator-complex-python/releases/tag/v0.3.0-beta.1) и [New Interface 0.4 Beta 1](https://github.com/Hazernit/operator-complex-python/releases/tag/v0.4.0-beta.1). У каждого — два ZIP (Windows/macOS) и `SHA256SUMS.txt`; их загрузка через первоначальный скрипт **уже выполнена**. Повторно запускать `publish-both-betas.sh` для этих тегов не нужно.

**Оговорка по качеству:** первоначальный Windows-архив создавался вне Windows и **не тестировался на реальном Windows x64**, а macOS `.app` ad-hoc signed. Это бета, не стабильный выпуск. Не переименовывайте этот факт в «проверено» без теста самих ZIP на двух системах.

## Последующие обновления — GitHub Actions

Автоматизированный workflow: [Desktop beta packages](../.github/workflows/desktop-betas.yml).

Ветка `main` содержит инструменты сборки, ветка `develop/technical` — развиваемый технический прототип. Для новой беты:

1. Внести изменения в соответствующую ветку через обычный PR; прогнать тесты и утвердить код.
2. Перейти в **Actions → Desktop beta packages → Run workflow**.
3. Выбрать `edition`: `technical` или `new-interface`; указать **новый** tag вида `v0.3.0-beta.2` или `v0.4.0-beta.2` (или `v0.3.1-beta.1` после bump).
4. CI сам собирает переносимые дистрибутивы на **Windows 2022 x64** и **macOS 15 Apple Silicon**, запускает `--verify-bundle` и `--smoke-test` именно для готовых пакетов, проверяет ZIP, формирует SHA-256 и публикует **GitHub prerelease**.
5. Если хотя бы один сборочный job падает, **Release не создаётся**. Одинаковый тег нельзя повторно создать/перезаписать. Новый выпуск — новый тег.

В отличие от первых архивов, будущие сборки использует `PyInstaller` на целевой ОС, из исходников текущей редакции, с Python 3.12, PySide6-Essentials 6.12.0 и PyInstaller 6.16.0. Формат внутренней папки может отличаться от первой Beta 1, но полученный пакет тестируется отдельно.

Это **автоматическая доставка новой версии**, а **не автообновление уже установленного приложения**. Автообновление UI, подписи Authenticode/Developer ID, проверка лицензий, SBOM и интеграционные проверки — отдельные этапы. Не заявлять наличие автообновления в текущей бете.
