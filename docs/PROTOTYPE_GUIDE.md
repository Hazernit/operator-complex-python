# Подробное руководство по прототипу desktop 0.4

> Подробное техническое описание **текущего локального desktop-прототипа 0.4**, вынесенное из главного README. Все команды ниже выполняются из **корня репозитория**. Сведения о физике и датчиках относятся к учебной симуляции, а не к проверенным реальным платформам. Актуальные правила командной разработки, версии и быстрый запуск: [основной README](../README.md).

Настольное приложение для БПЛА, НРТК и БЭК. На карте отображается **одна выбранная платформа**; переключение выполняется в списке слева. Есть общие органы управления, отдельные модели движения, демонстрационные датчики и воспроизведение записей из TXT.

Прототип работает локально. Встроенные платформы, датчики и примеры файлов используют тестовые данные. Параметры моделей не измерены на конкретных аппаратах; это учебная симуляция, а не откалиброванный цифровой двойник. Подключение физических роботов, ROS 2, backend и видео остаются следующими этапами.

## Новый интерфейс

Светлое рабочее пространство на PySide6 / Qt Widgets: нейтральные поверхности, индиго как единый акцент, системная типографика и короткие переходы. Это переработка компоновки и взаимодействий, подключённая к исходным сервисам симуляции и датчиков.

- **Слева:** поиск по имени, типу и ID, прокручиваемый список любого числа платформ, состояние, заряд, связь, экспорт и настройки.
- **В центре:** обзор карты, подробная телеметрия, карта с датчиками/TXT, журнал и честное пустое состояние камер. «Ещё» открывает предупреждения, профиль и сведения об интеграции.
- **Справа:** четыре основных показателя, ручное управление или миссия. СТОП закреплён снизу и остаётся доступен при переключении представлений. Это остановка учебной модели, не аппаратная аварийная кнопка.
- **Карта:** масштаб вокруг курсора, панорамирование, центрирование платформы, вписывание области, пронумерованные цели, маршрут, измеренный трек, курс и слои датчиков. Условные XY не выдаются за географию.
- **Данные:** неизвестные, отсутствующие в TXT и устаревшие показания различаются. При отсутствии свежей телеметрии ручной ввод, запуск и продолжение миссии блокируются; СТОП остаётся доступен.
- **Команды:** результат появляется после возврата сервиса и означает принятие локальной моделью. Ошибки выводятся в контексте платформы. Подтверждений физического контроллера нет; GOTO заменяется маршрутом из одной точки. Отдельных GOTO/RETURN_HOME адаптер не предоставляет.
- **TXT:** разбор и расчёт границ выполняются в фоновом потоке. Текущий источник меняется только после полной проверки. Можно отменить ожидающий импорт через «К симуляции»; переключение устройства не перенаправляет результат на другой робот.
- **Клавиатура:** Ctrl+F / Cmd+F — поиск; Ctrl+Shift+F / Cmd+Shift+F — полноэкранный режим. Удержание движения сбрасывается при уходе фокуса, выборе платформы, открытии настроек и смене рабочего представления.
- **Анимация:** короткое появление центрального контекста; настройка «Уменьшить анимацию» отключает переходы. Карта следует измеренным данным без декоративного движения. Настройка действует в текущем сеансе.

Токены и компоненты: [design-system.md](design-system.md). Матрица сохранения функций: [ui-audit.md](ui-audit.md). Фактические проверки: [ui-validation.md](ui-validation.md). Снимки окон: [доступные изображения новой версии](screenshots).

## Запуск

На macOS откройте `run.command` двойным щелчком или выполните из распакованной папки:

```bash
sh run.command
```

Также работает `python3 bootstrap.py`. Запускатель ищет Python 3.11+, создаёт `.venv`, устанавливает зависимости и открывает приложение. При первом запуске нужен интернет. Папка `.venv` создаётся отдельно на каждом компьютере и не входит в архив. Готовое окружение используется повторно; путь к Python при необходимости задаётся переменной `OPERATOR_PYTHON`.

Ручная установка с Python 3.11 или новее:

```bash
python3 -m venv .venv
source .venv/bin/activate
python -m pip install -r requirements.txt
python main.py
```

Если окружение уже создано, на macOS/Linux достаточно:

```bash
.venv/bin/python main.py
```

В Windows активируйте `.venv\Scripts\activate` в командной строке или `.venv\Scripts\Activate.ps1` в PowerShell. Альтернативная точка входа — `python -m operator_stub`. Зависимость `PySide6-Essentials` содержит необходимые модули Qt; установка ROS для запуска не нужна.

## Клавиатура и ручное управление

Клавиатура включена по умолчанию. Выберите платформу и используйте **WASD без удержания пробела**:

| Клавиши | Действие |
| --- | --- |
| W / Ц / ↑ | Тяга вперёд |
| S / Ы / ↓ | Тяга назад |
| A / Ф / ← | Поворот влево |
| D / В / → | Поворот вправо |
| Пробел / Esc | СТОП; активное задание переходит на паузу |

Можно удерживать две клавиши одновременно: например, W+D. Поддерживаются английская и русская раскладки, верхний и нижний регистр. Ползунок интенсивности задаёт величину команды. Кнопки со стрелками работают при удержании.

Отпускание клавиш убирает соответствующие команды: модель постепенно снижает скорость, сохраняя предусмотренную для её типа инерцию. **СТОП** — отдельная немедленная остановка учебной среды. Это различие не задаёт поведение будущей физической аварийной остановки.

При потере фокуса окна, отключении клавиатуры или выборе другой платформы ручной ввод сбрасывается. В полях ввода и диалогах клавиши остаются обычным текстом и навигацией. Перед ручным управлением нужно отменить выполняющуюся или приостановленную миссию. При воспроизведении TXT управление движением отключено.

## Разные модели движения

| Платформа | Поведение в симуляции |
| --- | --- |
| НРТК | Дифференциальный привод: плавный разгон, торможение и изменение угловой скорости. Возможен поворот на месте. |
| БЭК | Одновинтовой корпус с рулём: продольная инерция и запаздывание курса по упрощённой модели Nomoto. Вращение ограничено 20°/с; руль без движения не разворачивает корпус. Поворот выполняется по дуге. |
| БПЛА | Мультикоптер в горизонтальной плоскости: ограниченное ускорение, инерция вектора скорости и плавное изменение курса. Высота удерживается на 8 м. |

Для БЭК удерживайте W+A или W+D: сначала появится ход, затем корпус начнёт плавно поворачивать. Одиночная A/D у стоящей лодки не создаёт поворота. Модель соответствует выбранному корпусу с рулём; будущий катамаран с независимыми движителями может требовать другого поведения.

Учебное поле имеет размер 100 × 70 м и содержит статические препятствия. При столкновении с границей или препятствием срабатывает остановка симулятора. Управление по точкам учитывает различия моделей, включая опережение поворота лодки. Планировщик обхода препятствий не реализован: путь следует задавать по свободной области.

Параметры, допущения и источники описаны в [заметках о моделях](model-notes.md). Ветер, течение, гидродинамика полного корпуса, крен и тангаж не моделируются.

## Карта, датчики и маршрут

В симуляции показания зависят от положения и геометрии среды:

- LiDAR строит лучи до границ и препятствий; отражения отображаются отдельными точками.
- Сонар возвращает расстояние в пределах широкого угла обзора. Он изображается сектором и дугой: одного значения недостаточно, чтобы назвать точный азимут препятствия.
- Для БЭК вертикальный эхолот показывает учебную глубину отдельным числом. Его значение не превращается в препятствие на горизонтальной карте.
- Положение на карте поступает из синтетической локализации — имитации одометрии и курса. Это явно обозначенный источник данных.

**Синяя линия** — пройденная траектория по положениям локализации. **Зелёный пунктир** — заданный маршрут. Отдельные флажки управляют отображением датчиков и накоплением LiDAR-отражений. Накопленная картинка — совмещение измерений с известными положениями; полноценный SLAM не реализован.

Для маршрута включите добавление точек и щёлкайте левой кнопкой на карте. Во вкладке «Маршрут» доступны запуск, пауза, продолжение, отмена и сохранение/загрузка JSON. Колесо мыши меняет масштаб, правая или средняя кнопка перемещает карту, «Вписать» возвращает подходящий обзор.

Положение, маршрут и след сохраняются отдельно для каждой платформы. Переключение не отменяет задания других платформ; общие события доступны через «События», предупреждения — через меню «Ещё» и общую полосу при активных предупреждениях.

## Загрузка датчиков из TXT

1. Выберите платформу слева.
2. Нажмите **«Датчики»** в навигации рабочего пространства.
3. Загрузите свой TXT/CSV либо выберите встроенный пример.
4. Нажмите воспроизведение. Ползунок позволяет перейти к нужному времени, переключатель скорости — ускорить или замедлить запись.
5. Нажмите возврат к симуляции, чтобы снова управлять выбранной моделью.

Запись воспроизводится только для просмотра: приложение не меняет файл и не отправляет команды роботу. Ручное управление и выполнение миссий в этом режиме недоступны. Заряд и связь, которых нет в формате записи, показываются как неизвестные; тестовые значения симулятора не подставляются.

Примеры находятся в папке [examples](../examples):

- [lidar-room.txt](../examples/lidar-room.txt) — локализация и LiDAR;
- [sonar-route.txt](../examples/sonar-route.txt) — локализация и широкие сонарные сектора;
- [mixed-route.txt](../examples/mixed-route.txt) — совмещённая запись LiDAR и сонара.

Все три примера сгенерированы для демонстрации, не сняты с физических устройств.

Файл содержит время, положение и измерения. Минимальный пример UTF-8 с разделителем-запятой:

```csv
time_s,type,x_m,y_m,heading_deg,angle_deg,range_m,fov_deg,max_range_m
0,pose,10,10,0,,,,
0,lidar,,,,0,5,0,20
0,sonar,,,,90,8,30,20
1,pose,12,10,10,,,,
```

`pose` задаёт положение и курс, `lidar` — узкий луч, `sonar` — широкий сектор. Время указано в секундах, координаты и дальности — в метрах, углы — в градусах. Ось X направлена вправо, Y вверх, курс 0° — вдоль +X; положительные углы направлены против часовой стрелки. Угол датчика задаётся относительно корпуса. Дополнительные смещения описывают установку датчика на корпусе.

**Для глобальной траектории нужны строки `pose`.** Дальности LiDAR/сонара сами по себе не определяют, где находился робот. В дальнейшем `pose` может приходить от одометрии с IMU, GNSS или отдельного алгоритма локализации. При воспроизведении положение плавно интерполируется, а скан сохраняет место и время своего измерения — старые отражения не перемещаются вместе с роботом.

Полная спецификация, ограничения файла, `inf` для отсутствия отражения и примеры смещений: [sensor-format.md](sensor-format.md).

## Телеметрия, события и предупреждения

В симуляции доступны заряд, качество связи, режим, скорость и профильные показания. Заряд и связь пока являются тестовыми каналами. Высота БПЛА, расстояние до препятствия НРТК и глубина БЭК вычисляются выбранной учебной моделью.

Общие показатели сопоставляются по полю `semantic`: `battery_percent` и `link_quality_percent`. Отсутствующее значение и `null` означают «Нет данных»; 0% — известное критическое состояние. При отключении прошлое измерение не выдаётся за актуальное. Повторное подключение само не возобновляет движение.

| Состояние | Отображение |
| --- | --- |
| Заряд ≤ 20% / ≤ 10% | Предупреждение / критическое предупреждение |
| Связь ≤ 30% / ≤ 10% | Предупреждение / критическое предупреждение |
| Подключённый источник не обновлял данные более 2 с | Устаревшая телеметрия |
| Источник отключён | Предупреждение и последнее известное положение |

Пороги служат для проверки интерфейса и ещё не являются утверждёнными правилами эксплуатации оборудования. Представление «Камеры» сообщает об отсутствии провайдера видеопотока.

## Конфигурация и модули

Файл [config/demo_platforms.json](../config/demo_platforms.json) содержит примеры платформ с уникальными `id`, `name`, `kind`, начальным положением `initial_pose`, полями `telemetry_fields` и возможностями `manual`/`mission`. Запуск с ним:

```bash
python main.py --config config/demo_platforms.json
```

При запуске без аргумента используется встроенный набор. Состав будущего оборудования пока не определён; произвольные дополнительные каналы можно описывать подписью, единицей и значением. Настройка `demo` с `kind: "wave"`, `amplitude` и `period_s` позволяет колебать произвольный числовой канал. Известные модельные каналы, такие как `demo_altitude`, `demo_obstacle_distance` и `demo_depth`, вычисляются симулятором.

| Модуль | Ответственность |
| --- | --- |
| `models.py` | Состояния, положение, телеметрия и события |
| `presentation.py` | Общие показатели, предупреждения и профили платформ |
| `service.py` | Подключения, команды и жизненный цикл миссий |
| `motion.py` | Ограниченная динамика трёх типов платформ |
| `world.py` | Учебная среда, препятствия, пересечения лучей и глубина |
| `adapters/base.py`, `adapters/mock.py` | Контракт источника и локальный симулятор |
| `sensor_data.py` | Проверка TXT, кадры, интерполяция и координатные преобразования |
| `playback.py` | Независимое воспроизведение записи без команд движения |
| `map_widget.py` | Карта, слои датчиков, маршрут и интерактивный viewport |
| `workspace.py`, `design.py` | Компоновка, представления, токены, иконки и компоненты |
| `ui.py` | Связь интерфейса с сервисом, ввод, запись и предупреждения |
| `recording_loader.py` | Фоновая подготовка записей, результат в GUI-потоке |

Для реальной платформы потребуется согласовать протокол, сообщения, координаты, единицы измерения, режимы и подтверждение команд. Сменный адаптер преобразует сообщения оборудования в общую модель состояния. Блокирующий обмен должен выполняться вне потока интерфейса. Нормированные команды учебной среды требуют преобразования под конкретный контроллер; подключение ROS 2 и backend остаётся отдельной интеграцией.

## Проверки

Все автоматические проверки:

```bash
python -m unittest discover -s tests -v
```

Проверяются состояния и миссии, границы моделей движения, данные и преобразования датчиков, воспроизведение, предупреждения, отображение одной платформы, WASD/русская раскладка и работа клавиш при разном фокусе. Чистая логика проверяется без Qt; для GUI нужен PySide6.

Проверка настоящих кнопок и клавиатуры без открытия окна:

```bash
python main.py --smoke-test
```

Для сохранения снимка интерфейса добавьте `--screenshot tmp/stub-preview.png`. Результаты тестов относятся к программному прототипу; измерений конкретного физического аппарата ещё нет.


Повторяемая визуальная проверка трёх размеров окна и основных состояний:

```bash
python scripts/capture_workspace.py
```

Скрипт использует реальный Qt с offscreen-отрисовкой и сохраняет PNG в `output/screenshots`. Его сценарий отправляет команды только локальной симуляции. Для проверки HiDPI можно запустить с `QT_SCALE_FACTOR=2`. Состояния на снимках получены от модели или записи, а не подставлены в интерфейс.
