# Дизайн и развитие интерфейса 0.4

## Концепция

Спокойная светлая рабочая среда: системный шрифт, тонкие границы, функциональные пиктограммы и индиго как акцент. Навигация платформ, рабочее представление и органы управления имеют постоянные места. Карта получает основную площадь; таблицы появляются по запросу. Переключение представления не отменяет миссию.

Qt Widgets сохранён: исходный сервис уже отделён от транспорта, собственный QPainter подходит для карты и датчиков, GUI проверяется QtTest. Миграция на QML добавила бы мост состояний и риск регрессий без необходимости для текущих задач. WebView и веб-интерфейса нет. 3D не добавлено: доступна плоская поза с курсом и фиксированная высота БПЛА; пространственная модель создала бы ложное впечатление о данных.

## Токены

Источник токенов и общего stylesheet — `operator_stub/design.py`. Набор карты использует ту же палитру, геометрия отделена от сервисов. Тёмная тема не реализована; её следует вводить дополнительной полной палитрой и проверкой семантических цветов, а не частичной заменой фона.

| Canvas / поверхность / sidebar | `#f7f8fa` / `#ffffff` / `#f3f4f7` |
| Текст / вторичный / граница | `#252733` / `#757986` / `#e6e7ec` |

Основной реализованный переход — контекст рабочей области: opacity 0.82 → 1, OutCubic, 180 ms. Критические органы управления находятся за пределами эффекта. Настройка reduced motion останавливает переход немедленно. Другие motion tokens подготовлены для дальнейшего расширения, сложные анимации компоновки не заявляются готовыми. Движение карты отображается из состояний с шагом UI 50 ms, без экстраполяции; гарантированные 60 FPS не заявляются.

Пиктограммы нарисованы в проекте через QPainter: единая сетка 24×24, обводка 1.6 px, собственные изображения БПЛА, НРТК, БЭК и действий. Внешних наборов и лицензионных шрифтов нет. Растры кнопок создаются при DPR 2; карта и текст Qt масштабируются на плотных дисплеях.

## Компоненты и состояния

- PlatformDelegate: выбранное устройство выделено поверхностью, левой полосой и акцентной пиктограммой. Названия сокращаются при нехватке места; полный текст есть в tooltip. Поиск не подменяет выбранный контекст. Поддержан прокручиваемый список из конфигурации.
- Кнопки: default, hover, pressed, focus, disabled; основной START и семантический STOP. Подтверждение и ошибка команды живут в отдельном текстовом статусе, поэтому цвет не единственный сигнал.
- Карта: активная цель, номера точек, пройденный маршрут, измеренный трек, heading, stale/offline подпись, координаты указателя, масштабная линейка. LiDAR — точки; сонар — сектор неопределённости. Слои можно отключать.
- Метрики: заряд и связь сопоставляются только по semantic; unknown не становится нулём. В TXT отсутствующие метрики не заимствуются из симулятора. Последние значения сереют при устаревании.
- Подробности: доступная для клавиатуры таблица, фильтрованный журнал, общий список предупреждений с переходом к платформе.
- Настройки: уменьшение анимации, честное описание источника; изменения применяются после OK. Cancel сохраняет текущие значения. Хранения настроек между запусками пока нет.
- Импорт: фоновые parsing + bounds, loading-текст, отмена результата, ошибка без подмены источника. Worker не касается виджетов и команд.

## Операторские сценарии

После запуска подключены локальные симуляторы. Выбор платформы меняет карту, метрики, профиль и органы управления, сохраняя чужие маршруты. В ручном режиме удерживаются стрелки/клавиши; отпускание сбрасывает ввод. Маршрут задаётся точками на карте или загружается JSON, затем START; PAUSE/RESUME и отмена остаются в том же контексте.

При disconnect или stale новые команды движения блокируются, положение маркируется последним известным. Повторный connect не возобновляет миссию. Общие критические предупреждения видны независимо от выбора платформы. «Датчики» сочетает карту и playback/слои, «Обзор» разворачивает ту же карту на всё пространство. Камера честно сообщает об отсутствии видеопровайдера.

На меньшем окне приоритет отдан СТОП и основным метрикам: органы вторичного управления прокручиваются внутри панели; splitter регулирует доли карты/датчиков. При высоте от 980 px показывается дополнительная история измеренной скорости; в записи она очищается, чтобы не смешивать источники.

## Подключение реальных платформ

Нужно реализовать RobotAdapter под согласованный транспорт и нормализовать координаты/единицы. Сетевой I/O должен работать в отдельном worker и публиковать снимки в поток сервиса. Текущий синхронный tick годится для MockAdapter, не для блокирующего сетевого вызова.

До работы с оборудованием потребуются явный тип источника, capabilities для специальных команд, timestamp последнего пакета, подтверждения с ID/таймаутом, состояния жизненного цикла команд и правила физического STOP. Отдельный географический viewport должен получать координатную систему из контракта, а не трактовать текущие XY как широту/долготу. Для видео нужен независимый provider с состояниями подключения и освобождением декодера; фальшивый поток не используется.
